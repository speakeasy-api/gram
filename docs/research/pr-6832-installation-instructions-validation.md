# PR #6832 installation instructions: evidence and validation

Publication note: this report preserves the investigation and local implementation chronology below. Commit/push and screenshot publication were subsequently authorized. The refreshed PR demo selects only three source-fingerprint-matched, visually reviewed images (personal Claude Code, Cowork, and Cursor), not all 18 local captures. These remain synthetic UI evidence, not real-account testing.

Reviewed 2026-09-28 against `origin/main...HEAD`, HEAD `5e083c45ed`. Live vendor documentation can change independently of this branch. Scope: all new installation paths in `setup-data.ts`, `InstallInstructionsDialog.tsx`, `PublishDialog.tsx`, their flow/download changes, shared governance copy, ZIP generation, and marketplace proxy. Existing organization instructions were also checked where the new branches reuse them. Unchanged Codex/OpenAI instructions are not newly validated here.

## Verdict

- **Claude Code: underlying personal-settings path is documented and credible.** Correct the server-managed versus endpoint-managed distinction, Owner role, rollout scope and activation wording. OTEL traces are explicitly beta. The generated token URL is a Speakeasy-specific authentication mechanism, not something Anthropic's documentation certifies end to end.
- **Cowork: ZIP installation and hooks are documented, but the justification for ZIP-only personal setup is wrong in current docs.** Personal private GitHub marketplaces are now explicitly documented. Pro/Max eligibility, current menus, hook-runtime validation, and the distinction between hooks and Team/Enterprise native monitoring must be explicit.
- **Cursor: local path, hooks, reload and Customize are documented.** Correct the “Allow Local Plugin Imports” instruction (team-admin dashboard control), current team-import menus, fresh-download update step, shell assumptions, and destructive replacement failure mode.
- **Do not call these end-to-end validated.** Source contracts, generator tests, dashboard tests and safe shell fixtures pass within their scope; no actual proprietary application or real account was used.

Evidence labels: **supported** = explicit current vendor contract; **conditional** = only under stated prerequisites; **contradicted** = current contract differs; **undocumented** = reviewed sources do not establish it (not proof of impossibility); **code-derived** = repository implementation, not external runtime proof. Vendor issue reports, including [anthropics/claude-code#28125](https://github.com/anthropics/claude-code/issues/28125), are historical/weaker evidence and cannot override current official docs.

### Precedence, OS, restart, and governance

- **Precedence:** [Settings → Settings precedence](https://code.claude.com/docs/en/settings#settings-precedence) gives managed → command line → project-local → shared-project → user. Within managed settings, [How Claude Code combines managed sources](https://code.claude.com/docs/en/managed-settings#precedence-within-the-managed-tier) ranks remote → MDM/OS → managed files → Windows HKCU. **Do not say all managed sources simply merge:** default selection uses the first source with a policy key, with documented cross-source exceptions, including `env`, and an opt-in merge mode.

- **OS coverage:** [Managed settings → Where each mechanism stores the policy](https://code.claude.com/docs/en/managed-settings#where-each-mechanism-stores-the-policy) documents managed files under `/Library/Application Support/ClaudeCode/` on macOS, `/etc/claude-code/` on Linux/WSL, and `C:\Program Files\ClaudeCode\` on Windows; native macOS preferences and Windows registry are also available. **Endpoint management is not macOS-only.**

- **Initial activation / updates:** [Server-managed setup](https://code.claude.com/docs/en/server-managed-settings#configure-server-managed-settings): “next startup or hourly polling cycle.” [Plugin loading → When auto-update runs](https://code.claude.com/docs/en/plugins/loading#when-auto-update-runs): after the first message, Claude waits “a random delay of up to ten minutes”; “The running session keeps the versions it loaded”. Apply with `/reload-plugins` or next launch. **Add a fresh-session and verification step rather than implying immediate rollout.**

- **Verification:** [Monitoring → Quick start](https://code.claude.com/docs/en/monitoring-usage#quick-start): check `claude_code.session.count` for metrics and `claude_code.user_prompt` after submitting a prompt for logs. Trace receipt needs separate confirmation.

- **Governance note:** The imported statement, “Governing personal accounts in Claude Cowork and Claude Code Desktop is not possible at this time,” is **not defensible as a universal Claude capability claim**. [Managed settings → Where and when a policy applies](https://code.claude.com/docs/en/managed-settings#where-and-when-a-policy-applies) explicitly says local Cowork “reads the MDM or OS-level policy and the managed settings file on that device,” with VM/remote exceptions. This does **not** prove Speakeasy currently governs those personal accounts; label it a **Speakeasy integration limitation**, if that is the intended claim. User-installed telemetry alone is not tamper-resistant governance.

### Important route distinction

`DownloadObservabilityPlugin` creates an embedded hooks key. Generic `DownloadPluginPackage` (the plugin dialog's “Download as zip” menu) instead generates the selected plugin's MCP/skill package, uses plugin-read authorization, and does **not** mint that observability key. Do not attach the org-admin/embedded-hooks warning to every generic ZIP indiscriminately. The safe installer requires hook manifests/runtime files for observability setup, but permits generic plugin ZIPs without hooks. File checks do not establish hook execution or connector sign-in.
