# Admin users: local performance evidence

## Assessment / decision (2026-09-29)

**The provisional 300 ms budget is not met at 100k. These are local synthetic numbers, not production assurance.** No production index, schema, migration, or application-query change is proposed by this task.

- 10k: all page + count + actual-page-preview sums are below 166 ms.
- 100k: empty, selective email/org, common bare, and one-character requests remain below 248 ms; no-match, two-character, mixed, and repeated-org requests exceed 300 ms (matrix below).
- Actual plans show repeated membership/organization lookups inside correlated user predicates, especially count. Root estimates can predict only 1–2 user rows despite tens of thousands of matches. Warm shared-buffer hits do not make that CPU/loop cost cheap.
- Four temporary `pg_trgm` GIN indexes alone do not fix the shipped predicate shape: no-match page/count still total about 1,577 ms. They therefore do **not** justify shipping an index migration on their own.
- A tested candidate-ID UNION for **one bare term only** makes no-match page/count about 0.23 ms, but common `fictional` first-page/count becomes about 711 ms; `a` about 320 ms; `st` about 343 ms, before previews. It is not a universal replacement and does not implement the full grammar. Exact ordered IDs and count parity passed for all four experimental terms (100k, 0, 100k, 75k matches).
- Temporary GIN build: 606 ms. Three 1,000-name updates inside a rolled-back transaction: median 14.490 ms without GIN versus 20.582 ms with GIN (~42% higher here). This is a narrow write-cost probe, not general throughput evidence.
- Decision: retain Task 2 SQL and current schema. A future full-grammar query-shape optimization needs selective versus common/short-term planning and exact lifecycle/same-org parity, then remeasurement before selecting indexes. Performance target remains an explicit concern, not a claimed completion.

### Method and limits

PostgreSQL ran in the existing local test-container infrastructure on ARM64; the test creates/drops isolated clones. No customer or shared production dataset was queried. See per-profile PostgreSQL/version/memory settings below. Data has uniform fictional names, synthetic emails and modulo memberships; it is not a production-distribution model. No concurrent fixture tests were deliberately run during measurements. No service-management or broad infrastructure repairs were used.

Each reported query median is three `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) EXECUTE` runs, summing PostgreSQL planning and execution time. Request totals are **sums of component medians**, not measured HTTP wall latency or a three-run median of whole requests; they exclude network, serialization and Go overhead. Root buffers/estimates are from run 3, not sums of nested nodes. The slowest successful plan per profile is retained with compact recursive node statistics. Default `plan_cache_mode=auto` is used; repeated prepared calls may change custom/generic plans, so sequence is part of reproduction. All completed workload statements fit the 1,500 ms per-statement cap; none timed out. Request sums can exceed 1,500 ms because page/count are separate statements. Profile setup/index DDL cap is 5 s and lock timeout 1 s.

An initial exploratory run used the wrong positional pagination order and was discarded entirely. This final run uses generated `$5=offset, $6=limit` (overflow `$2=offset, $3=limit`), asserts expected totals and page lengths, and collects actual returned IDs for previews. The tool's outer 20-second shell deadline interrupted its wrapper during the corrected run; the bounded Go test remained alive and completed successfully (78.966 s), observed by a bounded monitor. No duplicate measurement process was launched. The final matrix and retained plans below are from that completed corrected run only.

## Exact prepared statements

Generated Task 2 SQL; parameter order is unchanged. PostgreSQL infers parameter types from casts.

```sql
PREPARE adminListUsers AS -- name: AdminListUsers :many
SELECT u.id, u.email, u.display_name, u.last_login
FROM users u
WHERE u.deleted_at IS NULL AND u.workos_deleted_at IS NULL
AND NOT EXISTS (SELECT 1 FROM unnest($1::text[]) p(pattern) WHERE NOT (u.display_name ILIKE p.pattern))
AND NOT EXISTS (SELECT 1 FROM unnest($2::text[]) p(pattern) WHERE NOT (u.email ILIKE p.pattern))
AND (cardinality($3::text[]) = 0 OR EXISTS (
    SELECT 1 FROM organization_user_relationships m JOIN organization_metadata o ON o.id = m.organization_id
    WHERE m.user_id = u.id AND m.deleted IS FALSE
    AND NOT EXISTS (SELECT 1 FROM unnest($3::text[]) p(pattern) WHERE NOT (o.name ILIKE p.pattern OR o.slug ILIKE p.pattern))
))
AND NOT EXISTS (
    SELECT 1 FROM unnest($4::text[]) p(pattern)
    WHERE NOT (u.display_name ILIKE p.pattern OR u.email ILIKE p.pattern OR EXISTS (
    SELECT 1 FROM organization_user_relationships m JOIN organization_metadata o ON o.id = m.organization_id
    WHERE m.user_id = u.id AND m.deleted IS FALSE AND (o.name ILIKE p.pattern OR o.slug ILIKE p.pattern)
 ))
)
ORDER BY lower(u.email), u.id LIMIT $6::int OFFSET $5::int
;
PREPARE adminCountUsers AS -- name: AdminCountUsers :one
SELECT count(*)
FROM users u
WHERE u.deleted_at IS NULL AND u.workos_deleted_at IS NULL
AND NOT EXISTS (SELECT 1 FROM unnest($1::text[]) p(pattern) WHERE NOT (u.display_name ILIKE p.pattern))
AND NOT EXISTS (SELECT 1 FROM unnest($2::text[]) p(pattern) WHERE NOT (u.email ILIKE p.pattern))
AND (cardinality($3::text[]) = 0 OR EXISTS (
    SELECT 1 FROM organization_user_relationships m JOIN organization_metadata o ON o.id = m.organization_id
    WHERE m.user_id = u.id AND m.deleted IS FALSE
    AND NOT EXISTS (SELECT 1 FROM unnest($3::text[]) p(pattern) WHERE NOT (o.name ILIKE p.pattern OR o.slug ILIKE p.pattern))
))
AND NOT EXISTS (
    SELECT 1 FROM unnest($4::text[]) p(pattern)
    WHERE NOT (u.display_name ILIKE p.pattern OR u.email ILIKE p.pattern OR EXISTS (
    SELECT 1 FROM organization_user_relationships m JOIN organization_metadata o ON o.id = m.organization_id
    WHERE m.user_id = u.id AND m.deleted IS FALSE AND (o.name ILIKE p.pattern OR o.slug ILIKE p.pattern)
 ))
)
;
PREPARE adminListUsersOrganizationPreviews AS -- name: AdminListUsersOrganizationPreviews :many
WITH ranked AS (
    SELECT m.user_id, o.id, o.name, o.slug, o.disabled_at,
    count(*) OVER (PARTITION BY m.user_id) AS organization_count,
    row_number() OVER (PARTITION BY m.user_id ORDER BY lower(o.name), o.slug, o.id) AS position
    FROM organization_user_relationships m JOIN organization_metadata o ON o.id = m.organization_id
    WHERE m.user_id = ANY($1::text[]) AND m.deleted IS FALSE
)
SELECT user_id, id, name, slug, disabled_at, organization_count FROM ranked WHERE position <= 3
ORDER BY user_id, position
;
PREPARE adminListUserOrganizations AS -- name: AdminListUserOrganizations :many
SELECT o.id, o.name, o.slug, o.disabled_at
FROM organization_user_relationships m JOIN organization_metadata o ON o.id = m.organization_id
WHERE m.user_id = $1::text AND m.deleted IS FALSE
ORDER BY lower(o.name), o.slug, o.id LIMIT $3::int OFFSET $2::int
;
PREPARE adminCountUserOrganizations AS -- name: AdminCountUserOrganizations :one
SELECT (SELECT count(*) FROM organization_user_relationships m WHERE m.user_id = u.id AND m.deleted IS FALSE) AS total
FROM users u WHERE u.id = $1::text AND u.deleted_at IS NULL AND u.workos_deleted_at IS NULL
;
```
