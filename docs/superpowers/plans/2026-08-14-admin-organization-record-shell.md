# Admin Organization Record Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the admin organization detail page into a record with three routed views behind a contextual sidebar nav, moving existing content rather than adding any.

**Architecture:** `routes/organizations.$idOrSlug.tsx` becomes a TanStack Router layout route that owns the record read, renders record-level chrome (header and trial callout), and renders `<Outlet/>`. Four child routes sit under it. `AppSidebar` branches on `useMatchRoute` to render a record nav instead of the global nav, and `site-header.tsx` builds a breadcrumb from `useMatches()` instead of slicing the pathname.

**Tech Stack:** React 19, TypeScript, TanStack Router (file-based routes, `routeTree.gen.ts` is generated), TanStack Query, TanStack Table, shadcn/ui on Radix, Tailwind, vitest with `@testing-library/react`.

**Spec:** `docs/superpowers/specs/2026-08-14-admin-organization-record-shell-design.md`

- Trial wording comes from `TRIAL_LABELS` in `@/lib/trialLabels`. Never write a trial state's words by hand.
- Comments explain why, never what. Do not add a comment that restates the line below it.

- [ ] **Step 3: Write the layout**

Create `client/admin/src/pages/organization/RecordLayout.tsx`. This step gives it the record read, the error path and the outlet. The header and callout arrive in Task 5; leave the name in a plain `<h4>` for now so the test has something to find.

```tsx
import type { JSX } from "react";
import { useQuery } from "@tanstack/react-query";
import { Outlet, useParams } from "@tanstack/react-router";

import { organizationQuery } from "@/lib/adminQueries";
import { errorMessage } from "@/lib/gramAdminApi";

export function RecordLayout(): JSX.Element {
  const { idOrSlug } = useParams({ from: "/organizations/$idOrSlug" });
  const { data, isLoading, isError, error } = useQuery({
    ...organizationQuery(idOrSlug),
    enabled: !!idOrSlug,
  });

  if (isLoading) {
    return <span className="text-muted-foreground text-sm">Loading...</span>;
  }

  // No chrome and no outlet for a record that failed to load. A contextual
  // nav and four views over nothing strand the operator with a back link.
  if (isError || !data) {
    return (
      <span className="text-muted-foreground text-sm">
        Error: {errorMessage(error)}
      </span>
    );
  }

  return (
    <div className="flex min-h-0 flex-1 flex-col gap-6">
      <h4 className="text-[1.438rem] leading-[1.6] font-light">{data.name}</h4>
      <Outlet />
    </div>
  );
}
```

```tsx
import type { JSX } from "react";
import { createFileRoute, useParams } from "@tanstack/react-router";
import { useQuery } from "@tanstack/react-query";

import { organizationQuery } from "@/lib/adminQueries";
import { Overview } from "@/pages/organization/Overview";

function OverviewRoute(): JSX.Element | null {
  const { idOrSlug } = useParams({ from: "/organizations/$idOrSlug" });
  const { data } = useQuery(organizationQuery(idOrSlug));
  if (!data) return null;
  // Keyed, so an unsaved draft cannot follow the operator to another record.
  return <Overview key={data.id} org={data} />;
}

export const Route = createFileRoute("/organizations/$idOrSlug/")({
  component: OverviewRoute,
});
```

The three other child routes follow the same shape with `Projects`, `Members` and the single-project view. Repeat the code rather than abstracting it: five near-identical eight-line route files are easier to read than one generic wrapper, and the router's `from` string differs in each.

`organizations.$idOrSlug.projects.$projectIdOrSlug.tsx` renders the existing `ProjectDetail` page component, reading its own `projectIdOrSlug` param.

The child reads the record from the query rather than taking it from the layout by prop. The spec asks for the record to travel down as a prop; TanStack Router's file routes render through `<Outlet/>` and cannot be handed one, and reading the same `queryOptions` from the same client returns the identical object, so there is still one answer per render. That is the reason for the deviation.

```bash
cd ../.. && aube install --frozen-lockfile
```

`--lockfile-only` keeps pnpm away from the aube-shaped `node_modules`, and
