Scan captured skill manifests for prompt injection at capture time and record any hit as an ordinary `risk_results` finding, anchored on a new nullable `skill_version_id`. Previously no skill content reached the prompt-injection judge at all: a Claude skill activation is reclassified to `skill.activated` for both the pre and post tool events, that event type persists no chat message, and `HookSkillData` carries no content field — so the manifest body only ever existed server-side inside the detached content upload, where the scan now runs. Findings follow the existing model with no parallel verdict state: no durable SAFE record, no scan backlog, no scheduled sweep, and no second judge call. Only a newly created version is judged, so a re-upload or a concurrent duplicate of the same content hash yields one finding rather than N, and scanning never fails the upload — capture has already committed by the time the judge runs, and every error from it is logged and swallowed. Two limits are deliberate: coverage is usage-based rather than catalog-based, so a version no agent ever loads is never judged, and scanning is policy-gated because `risk_results.risk_policy_id` is `NOT NULL`, so a project with no enabled `prompt_injection` policy at capture time gets no finding and enabling one later does not retroactively scan.
