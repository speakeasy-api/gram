Scan captured skill manifests for prompt injection at capture time and record the outcome as an ordinary `risk_results` row, anchored on a new nullable `skill_version_id`. Previously no skill content reached the prompt-injection judge at all: a Claude skill activation is reclassified to `skill.activated` for both the pre and post tool events, that event type persists no chat message, and `HookSkillData` carries no content field — so the manifest body only ever existed server-side inside the detached content upload, where the scan now runs. A completed judgement always records a row: a hit is a `found = TRUE` finding, and a clean verdict is a `found = FALSE` coverage record, mirroring the empty result rows the chat batch path already writes. That distinction is what separates "judged clean" from "never judged", which the read paths' existing `found IS TRUE` filters keep out of the findings UI. A judge that never answers records nothing at all rather than a clean row, so an outage cannot write down a durable claim that unjudged content is safe. Scanning is gated on whether any enabled policy still lacks a record for the version rather than on whether the version was newly created: content is immutable per version so a recorded scan is never repeated and the judge is never spent twice, while a version left unrecorded by a failed judge stays eligible, as does one captured before a `prompt_injection` policy existed. Scanning never fails the upload — capture has already committed by the time the judge runs, and every error from it is logged and swallowed. Two limits remain deliberate: coverage is usage-based rather than catalog-based, so a version no agent ever loads is never judged, and re-judging an eligible version requires the content to be uploaded again, which the relay only does the first time it sees a hash — so a version left unscanned by an outage is not retried on its own.
