Identity chaining is now its own section on a remote MCP server's settings page, below Identity. It shows whether chaining is on and which sign-ins this server uses, with a single Turn on or Turn off action, and the step the vendor needs (trusting the issuer, with a copyable URL) until it is on. It has no scope list of its own, and the vendor-wide EMA provider order is no longer shown on the server. It now appears for an organization user session issuer that Speakeasy's own issuer can vouch for, not only one that trusts an external identity provider. On a server whose sign-in trusts no external identity provider, Turn on also appends Speakeasy to the vendor's EMA provider order, behind the `ema-providers` rollout, and is disabled with the reason when it can't. The new `organizationRemoteSessionIssuers.addSpeakeasyEMAProvider` endpoint backs it: it only acts for a sign-in that trusts no external identity provider, never removes or reorders providers, and refuses to replace a vendor's default order while another server has a ready binding to that vendor through an external identity provider. Platform MCP guidance points administrators to the section.
