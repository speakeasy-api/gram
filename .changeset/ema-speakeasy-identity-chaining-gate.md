Enterprise Managed Authorization is now its own section on a remote MCP server's settings page, below Identity, with one Turn on or Turn off action. It reads as a chain: the sign-in people use, the identity provider that vouches for them, what the service trusts (each identity provider's issuer URL, folded away once the service has accepted it anywhere in the organization), and the client, each linking to where it is changed. The section shows "Working" only once the service has accepted a sign-in for that server. It now also appears for an organization-level sign-in that Speakeasy's own issuer can vouch for, not only one that trusts an external identity provider. A project-level sign-in gets a notice that an organization-level one is needed.

Who vouches is derived rather than chosen per server. With no saved order, a server whose sign-in trusts an external identity provider uses that provider alone, and a server whose sign-in trusts none uses the organization's Speakeasy issuer. Setting up Speakeasy never adds it behind an external provider, so nothing changes for existing integrations whose sign-in trusts an external identity provider. A saved order (`organizationRemoteSessionIssuers.setEMAProviders`) replaces that default for every server reaching the service; identity chaining tries each provider in turn after any failure, so an order that lists Speakeasy after an external provider lets Speakeasy vouch when that provider refuses someone.

The organization's Identity providers tab gains a Services table, one row per service Enterprise Managed Authorization reaches, with a page per service for the once-per-service trust step and the identity provider order (customize, reorder, save, or go back to the default). The Speakeasy provider page lists the services whose order can use Speakeasy, split by whether each has accepted it. These read the new `organizationRemoteSessionIssuers.listEMAServices` API: every vendor authorization server a binding or saved order names, with the organization-wide order, when the vendor last accepted each exact provider anywhere in the organization, and how many distinct live MCP servers reach it. `readEMA` reports, per provider, the same organization-wide acceptance, and, for the binding, when the vendor last accepted an assertion for it. Platform MCP guidance describes the default and saved-order rules.

The dashboard calls the feature Enterprise Managed Authorization everywhere people see it. "Identity chaining" stays only in code and API names.
