The Platform MCP guided flow can now deploy a user-supplied remote MCP server URL as a project source through a probe/register tool pair. The read-only `probe_remote_mcp` verifies the endpoint through the guardian egress policy (MCP initialize handshake, `tools/list`, RFC 9728/8414 OAuth discovery — auth-walled servers pass, dead or non-MCP endpoints are refused), shows the evidence, and issues a short-lived signed receipt; the mutating `register_remote_mcp_for_project` accepts only that receipt — never a raw URL — and registers a private `remote_url` source that flows through the existing onboarding, readiness, identity-provider-attachment, setup-handoff, and distribution lifecycle. Org MCP approval enforcement is respected end to end: blocked registrations report `await_org_approval` with the dashboard approvals path, and distribution refuses enforcement-blocked sources with a typed `blocked_pending_approval` error. The surface ships behind the `platform-mcp-remote-url` rollout flag plus the existing Platform MCP capability, with a deliberately tight probe budget, and a bundled `add-mcp-from-remote-url` skill guides agents through the flow without ever accepting secrets in chat.
