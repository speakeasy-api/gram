Requests proxied to a remote MCP server no longer copy the caller's Speakeasy credential and session headers (`Gram-Key`, `Gram-Session`, `Gram-Chat-Session`, `Gram-Project`, `Gram-Consent-*` and their `Speakeasy-AI-*` names) or tunnel transport headers upstream; caller assertion headers stay stripped as before. A remote server header can no longer be populated from `Authorization` or any of those headers. An existing optional row of that kind is no longer sent. An existing required one makes requests fail with an error naming the header until it is changed or removed, except that a required `Authorization` row is skipped whenever a connected upstream account supplies `Authorization`. To pass an upstream credential, have clients send it in a separate request header and read it from there, or store it as a static value; upstream OAuth replaces only `Authorization`. Header writes now also reject names that are not valid HTTP field names, values containing control characters other than tab, `Set-Cookie` and `Proxy-Authorization` destinations, a `Cookie` populated from the request, and a name that differs from an existing header only in case or in `_` versus `-`; new and updated names are stored in canonical form. The dashboard marks saved rows the proxy now refuses and explains how to replace them.
