The agent wizard now asks for the credential before the servers: Name, Credential, MCP Selection, MCP Authentication, then the API key or the platform's setup. For an agent running on a platform, MCP Selection shows the MCP authentication provider its token comes from, preselected as the one most of its servers use, and says how each server signs in. A chosen server whose own provider can't give tokens to agents can have the shared provider assigned to it there, after a confirmation that previews the change; this is offered only when nobody connects their own account through the server's current provider and the reader can edit the server, and otherwise links to its authentication settings. The platform's setup shows the same provider, offers only providers the agent's servers use, and names any server the token won't work at, where it used to preselect the organization's first shared provider, whose tokens the servers refused. Editing an agent still goes from its name to its servers, and an API-key agent's Credential step still issues a new key. The provider picker now lists every shared MCP authentication provider, and when the organization has none, MCP Selection offers to create one in the agent's project, which the agent's servers can then be assigned to.
