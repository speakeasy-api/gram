Record a served MCP request as a connected row at the request step, so connection health can tell when a caller who failed earlier is connected again. A row is written only when the caller got a successful result for a request with an id: no JSON-RPC error and no tool result marked as an error. An `initialize` writes none and leaves the window open, so the session's next request writes it with the client the session reported. Rows are sampled, not one per request or guaranteed for every connection: a connection is a named caller (a person, API key, agent or workload), a server or gateway member, and an app, and each server process writes at most one row an hour per connection, so there can be several an hour across replicas and another after a restart, while a very large organization's connections may wait longer under its budget. A failure re-arms the caller's connections at most once a minute: a gateway member's failure re-arms only that member, and any other failure on the server re-arms all of them. Nothing is written for anonymous callers, notifications, a response that could not be delivered, or a request or member call in which something failed. Served rows have their own per-organization budget and yield the write queue to failures, and an organization with logging off loses no counted event to them. They count in the 30-minute attempt summaries table and in the `mcp.connection.steps` metric as connected request steps, and are left out of daily connection outcomes, provider health and customer log exports.
