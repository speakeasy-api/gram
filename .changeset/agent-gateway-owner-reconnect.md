An agent gateway now tells an agent what is wrong with a server's credential and who can fix it, instead of telling it to ask a gateway administrator. A missing, rejected or expired connection says the server needs re-authentication and asks someone who can edit the agent to open its MCP sign-in step (`/<org>/projects/<project>/identities/agents/<agent>/edit?step=2`) and reconnect it. A 403 from the upstream says the upstream account may not do the call, which signing in again does not change. An agent not allowed to use a connection is sent to its permissions page instead of being told to reconnect, and a server no auth client serves goes to an admin of the server's project. A missing, rejected or expired credential configured on the server and shared by every caller, such as an API key or a service account, goes to an admin of the server's project on every gateway. A member that offers a service account beside a personal client the agent cannot use is still served by the service account. `connection_status` gives the sign-in link in its text and as `connectUrl` in its structured result, with `audience: "agent_editors"` and `reconnect: true` only on servers the agent connects through its own OAuth sign-in. No message names a person, and the links carry no credential.
