Hosted MCP servers now write their own hosting state, and the toolset's hosting fields mirror it. This is an API change: `toolsets.update` rejects `mcp_enabled`, `mcp_slug`, `mcp_is_public`, `network_access_mode` and `custom_domain_id` with a bad request error, `toolsets.checkMCPSlugAvailability` is removed, and `toolsets.setUserSessionIssuer` is deprecated: it now writes the session issuer through the hosted MCP server, answers with `Deprecation` and `Sunset` headers, refuses to unlink an issuer that identity-chaining bindings depend on (409), and will be removed on 2026-11-25. Use `mcpServers.update` for visibility, network access and the session issuer, and `mcpEndpoints.update` to change a hosted server's address. To detach a session issuer from a hosted server, set `clear_user_session_issuer` on `mcpServers.update`. A hosted server keeps a single address: `mcpEndpoints.create` adds one only to a hosted server that has none, for example after its custom domain was deleted, and a hosted server without an address cannot be enabled. New toolsets get their MCP server and a platform endpoint at creation.
