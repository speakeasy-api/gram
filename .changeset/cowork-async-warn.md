Risk policies are enforced in Claude Cowork again. Inside the Cowork VM, `speakeasy-hooks` now sends prompt, tool and permission events to the server as it does in Claude Code, so block, warn and quarantine policies act in real time and the session is captured per event. The transcript shipped from Stop now backfills what no hook sees: the first prompt, typed in chat before the session moved to Cowork, and assistant text. Both paths key prompts and tool calls by the ids Claude reports to both (prompt id and tool call id), so each message is stored once whichever path writes first. When a transcript arrives, the server also checks its newly shipped prompts against warn policies and the binary has Claude tell the user in the same conversation, which covers typed prompts that Claude Code can only warn about at a tool call. Cowork cuts off a hook's block text before the acknowledgement link, so a warn on a typed prompt there is confirmed by sending the same message again within 10 minutes; the confirmation is audited. A warned tool call in Cowork is answered with a new `ask` decision instead, so Claude shows its own permission prompt with the warning; the call runs only if the person allows it, and that run records the confirmation in the audit log. Cowork events now carry `session.surface: "cowork"`. Block messages now fill the `%{match}`, `%{entity}`, `%{policy}` and `%{rule}` placeholders, as warn and quarantine messages already did, so the Secrets preset no longer shows `%{match}` literally. In a block message `%{match}` is masked to at most four characters from each end and never more than a quarter of the value, because the block exists to keep the value out of the session and Claude's apps drop a hook message that repeats a live credential.
